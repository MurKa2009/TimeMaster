# Восстановление TimeMaster

Эта инструкция предназначена для случая, когда звонок, веб-интерфейс или прошивка перестали работать.

## 1. Проверьте питание

1. Подключите ESP8266 к USB.
2. Убедитесь, что используется USB-кабель с передачей данных.
3. Нажмите кнопку `Reset` на плате и подождите 20–30 секунд.

## 2. Проверьте COM-порт

Откройте терминал PlatformIO и выполните:

```powershell
C:\Users\murka\.platformio\penv\Scripts\platformio.exe device list
```

В списке должен появиться порт, например `COM3`.

Если порт не найден:

- переподключите USB-кабель;
- используйте другой USB-разъём;
- установите драйвер CH340;
- перезапустите VS Code.

## 3. Закройте Serial Monitor

Перед прошивкой обязательно закройте окно `Monitor` в VS Code.

Если монитор открыт, порт занят и появляется ошибка:

```text
PermissionError: could not open port COM3
```

## 4. Проверьте веб-интерфейс

Откройте один из адресов:

```text
http://esp.local/dashboard
http://IP-АДРЕС-УСТРОЙСТВА/dashboard
```

IP-адрес можно посмотреть в Serial Monitor после перезагрузки устройства.

Стандартные данные для входа:

```text
Логин: admin
Пароль: admin
```

Если пароль изменён, используйте изменённый пароль.

## 5. Сохраните профили и настройки

Перед `uploadfs` сохраните текущие данные.

В браузере откройте:

```text
http://esp.local/api/settings.json
http://esp.local/api/profiles.json
```

Введите логин и пароль администратора.

Профили можно скачать через PowerShell:

```powershell
curl.exe -u admin:ПАРОЛЬ http://esp.local/api/profiles.json -o profiles.json
```

Если `esp.local` не открывается, замените его на IP-адрес устройства.

## 6. Важное предупреждение про uploadfs

Команда `uploadfs` полностью перезаписывает файловую систему ESP8266.

Она загружает все файлы из папки `data`, включая:

```text
data/settings.json
data/profiles.json
```

Перед запуском проверьте, что эти файлы существуют и содержат актуальные данные. Не запускайте `uploadfs`, если локальные JSON-файлы пустые или старые.

## 7. Обновите веб-интерфейс

Закройте Serial Monitor и выполните:

```powershell
C:\Users\murka\.platformio\penv\Scripts\platformio.exe run --target uploadfs
```

Дождитесь сообщения:

```text
[SUCCESS]
```

## 8. Обновите прошивку

Для загрузки кода устройства выполните:

```powershell
C:\Users\murka\.platformio\penv\Scripts\platformio.exe run --target upload
```

После завершения снова дождитесь `[SUCCESS]`, затем нажмите `Reset`.

## 9. Если звонок не подаётся

Проверьте в веб-интерфейсе:

1. Указано правильное время.
2. Выбран правильный режим работы.
3. В режиме «По выбранному профилю» выбран профиль.
4. В режиме «По дням недели» у профиля указан нужный день.
5. В режиме «Все профили» отдельный профиль выбирать не нужно.
6. Время записано в формате `ЧЧ:ММ`, например `08:30`.
7. Профиль содержит хотя бы одну запись с началом и концом.
8. Длительность звонка больше нуля.

## 10. Если профили не отображаются

1. Нажмите `Ctrl+F5` в браузере.
2. Проверьте вход под аккаунтом администратора.
3. Откройте:

```text
http://esp.local/api/profiles.json
```

4. Если API возвращает ошибку, перезагрузите ESP8266.
5. Если проблема появилась после `uploadfs`, восстановите актуальный `data/profiles.json` и повторите загрузку.

## 11. Частые ошибки браузера

Ошибка:

```text
GET is not defined
```

означает, что в консоль браузера введён текст вроде `GET /api/settings.json` как JavaScript. Для проверки используйте:

```javascript
fetch("/api/settings.json")
  .then(response => response.json())
  .then(data => console.log(data));
```

Ошибка `503` у `/api/sync/device` означает, что устройство не получило календарное время. Подключите ESP8266 к Wi-Fi с доступом к NTP или установите время вручную.

## 12. Если ничего не помогло

1. Не запускайте `uploadfs` повторно, пока не сохранены профили и настройки.
2. Проверьте, что `data/settings.json` и `data/profiles.json` не пустые.
3. Закройте все окна Serial Monitor.
4. Переподключите ESP8266.
5. Выполните сначала `upload`, затем `uploadfs`.
6. После загрузки нажмите `Reset` и проверьте Serial Monitor на скорости `115200`.

## Безопасность

API защищён логином и паролем администратора. Используется HTTP Basic Authentication без HTTPS, поэтому не вводите пароль через общую или недоверенную Wi-Fi сеть.
